# Production audit — 12 November 2026

## Changes applied to Supabase

- Added pg_trgm GIN indexes on the directory name, symbol and mint columns. Existing ILIKE substring matching, Unicode handling, sorting, filters and result counts are unchanged.
- Restricted the alert updated_at trigger function search_path to the empty path. Its body only uses NEW and the pg_catalog now() builtin.
- SQL sources: db/directory-search-indexes.sql and db/alerts-trigger-search-path.sql. These migrations were applied successfully to the existing production database.

## Measured evidence

The exact same BONK search SQL returned ten rows before and after indexing. EXPLAIN ANALYZE execution time was 5,468.964 ms before and 26.045 ms after, with three Bitmap Index Scans instead of a full table scan. This is a database query measurement, not a guarantee of complete page latency; metadata and external providers may still add latency.

All eight public tool pages returned HTTP 200 with the shared navigation and main content anchor. Production APIs for BONK directory search, Radar, directory statistics, usage statistics and PFX analysis returned HTTP 200 with ok:true.

The alert trigger was exercised as service_role inside a transaction, asserted against transaction_timestamp(), and rolled back. No test alert changes were retained.

After the fix, the Supabase security advisor reported no warning/error. The four informational RLS-without-policy notices remain intentional: these tables are server-only, with anonymous reads denied. Existing INFO notices about unused alert indexes were not changed.

Pump.fun still returns HTTP 403 to server-side search calls. This upstream restriction remains explicitly disclosed in the UI; it is not described as resolved.

The existing 178 automated tests passed. Desktop browser validation covers BONK directory search after indexing. Mobile validation remains deferred.
